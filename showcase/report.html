Speculative decoding: when the extra draft pays off in production

Compiled by Periscope agent Model · claude-sonnet-4-6 Token budget · 14,892 ● grounded · 0.96

Summary

Speculative decoding accelerates auto-regressive LLM inference by using a small, fast draft model to propose tokens that a larger target model verifies in parallel ¹. When the draft's distribution closely matches the target's, the technique amortizes target-model FLOPs across multiple accepted tokens — yielding latency reductions of 1.6×–3× at iso-quality in published benchmarks ².

In production, the wins are real but conditional. They evaporate under one of three failure modes: (i) low acceptance rates at long contexts, (ii) draft model overhead exceeding gain on small targets, and (iii) KV-cache pressure on the verifier in batch=1 streaming.

TL;DR. Worth turning on for Sonnet-class and larger when serving chat (batch=1, streaming). For batch≥16 or models below 8B params, the verification cost typically erases the win.

How it works

A draft model proposes γ tokens. The target model is run once over those γ candidates plus one trailing position, producing γ+1 logit distributions in a single forward pass ¹. Each candidate is accepted with probability min(1, p_target(x) / p_draft(x)). The first rejection terminates the chain, sampling one fresh token from a residual distribution. Output is exactly equivalent in distribution to a vanilla target-model sample.

Two implementation families exist in production. Tree-based drafting ³ increases acceptance by branching at low-confidence positions; n-gram and prompt-lookup avoid the draft model entirely by extracting candidates from the prompt itself — useful for code completion and RAG response synthesis.

The penalty case is illustrative: at batch=32, target-model utilization is already high, the draft model itself consumes scheduler slots, and verification logits inflate KV memory — so wallclock time slightly degrades. vLLM exposes this as a per-request flag; teams typically gate it on batch < 8 ⁴.

Production deployment notes

vLLM ships speculative decoding behind --speculative-model, with EAGLE-2 and Medusa as drop-in heads ⁴. The default acceptance threshold (typically γ = 4) works well for most prompts; longer chains require online tuning ³. Anthropic and Bedrock surface this transparently as a server-side optimization; OpenAI does not document it but several inferred behaviours suggest it is enabled for streaming chat.
